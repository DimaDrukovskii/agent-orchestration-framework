# План: голосовой интерфейс звонка (ветка `feature/call-ui`)

Записано утром 2026-10-10, перед `/compact` основной переписки — чтобы продолжить без потери контекста в том же окне, и чтобы можно было переслать этот документ в другую переписку как есть.

## Текущее состояние (подтверждено рабочим, не трогать без причины)

- Hermes-агент работает в Docker (`docker/docker-compose.yml`). Провайдер — Polza AI: `LLM_PROVIDER=polza`, модель `anthropic/claude-sonnet-4`, `POLZA_BASE_URL=https://polza.ai/api/v1` (OpenAI-совместимый, через `AsyncOpenAI` в `src/agent/hermes_agent.py._run_openai`).
- Бэкенд хранения — SQLite по умолчанию (`cache_backend`/`storage_backend="sqlite"`), Redis/Supabase не требуются.
- Текстовый диалог подтверждён живыми тестами (curl + веб-виджет): маршрутизация (`transfer_to_department`), ответы по базе знаний (`search_knowledge_base`), многошаговый контекст в рамках `session_id`.
- `demo/index.html` — рабочий чат-виджет на `main`, с полем `X-API-Key` (дефолт `test-local-key`, см. `keyInput.value = storeGet("mts_api_key") || "test-local-key"`), и заготовкой под микрофон (`micBtn`, проверка `SpeechRecognitionImpl`) — пока не доведена до полноценного голосового интерфейса.
- Контейнеры `docker-app-1` / `docker-redis-1` уже подняты и работают, `.env` в корне репо настроен (`LLM_PROVIDER=polza`, ключ Polza внесён) — перезапускать не нужно, если не менять код.
- Ветка `feature/call-ui` создана от `main` 2026-10-10, пока без коммитов.

## Запрос пользователя, который привёл к этой ветке

Диалог "ощущается как переписка двух нейронок", а не как звонок. Нужен отдельный интерфейс — как в ElevenLabs Agents (пользователь смотрел `elevenlabs.io/docs/overview/intro`, раздел ElevenAgents): полноценный "экран звонка" с микрофоном и трубкой, в который заходишь как на сайт и реально разговариваешь с агентом голосом, а не печатаешь.

Также отдельно попросил:
1. Голос агента должен звучать "более живо".
2. Сама речь (текст ответа) не должна быть всегда одной средней фразой — агент должен варьировать длину ответа в зависимости от сложности запроса (короткий вопрос → короткий ответ, сложный → развёрнутый).
3. Планирует подключаться по своему локальному IP (не обязательно localhost) — значит интерфейс должен быть доступен не только с `localhost:8000`.

## Принятое решение по голосу (подтверждено пользователем через явный выбор)

**TTS и STT — браузерные (Web Speech API), не ElevenLabs/Yandex.** Причина: бесплатно, без API-ключа, работает прямо сейчас в Chrome/Safari на Mac, укладывается в срок "до обеда". Осознанный компромисс: звучит заметно синтетичнее ElevenLabs, но это сознательный выбор ради дедлайна, не забытая деталь. Если по ходу дня появится ключ ElevenLabs — это отдельная, более поздняя доработка (замена `speechSynthesis.speak()` на реальный TTS-запрос), не блокирует MVP.

## Что строить (ещё не сделано на момент записи этого плана)

1. **Новая страница `demo/call.html`** — отдельный интерфейс звонка (не трогает существующий `demo/index.html`):
   - Экран "Соединяем..." при открытии (имитация дозвона — без Twilio, чисто фронтенд-анимация/пауза).
   - UI как в телефоне: кнопка "Взять трубку" / "Сбросить", кнопка микрофона (mute/unmute), таймер длительности звонка.
   - STT: `window.SpeechRecognition` / `webkitSpeechRecognition`, `lang="ru-RU"`.
   - TTS: `window.speechSynthesis`, `SpeechSynthesisUtterance`, `lang="ru-RU"` — выбрать голос поестественнее из `speechSynthesis.getVoices()`, если доступен русский голос лучше дефолтного.
   - Цикл: слушаем → по завершении фразы останавливаем распознавание → шлём текст в `POST /api/hermes/dialog` (тот же контракт, что в `demo/index.html`, тот же `X-API-Key`) → озвучиваем `agent_response` через TTS → **на время озвучки распознавание должно быть выключено** (иначе микрофон поймает голос агента из динамиков как будто это абонент говорит) → после окончания озвучки снова включаем распознавание.
   - Хранить `session_id` на всю "сессию звонка", как в `demo/index.html`.

2. **Технический риск, который нужно явно решить, не забыть**: доступ по локальному IP (не `localhost`) для микрофона.
   - `getUserMedia`/`SpeechRecognition` требуют "secure context": `https://` или `localhost`. Обычный `http://192.168.x.x:8000` **заблокирует микрофон** в большинстве браузеров — это не баг кода, а политика браузера.
   - Варианты (выбрать один, в порядке простоты):
     a. Тестировать только с ноутбука через `localhost:8000` — просто, но не даёт зайти с телефона/другого устройства.
     b. На устройстве, с которого заходишь по LAN IP: `chrome://flags/#unsafely-treat-insecure-origin-as-secure` → добавить `http://<LAN-IP>:8000` → релонч браузера. Быстро, но ручная настройка на каждом устройстве.
     c. Поднять самоподписанный HTTPS на сервере (uvicorn `--ssl-keyfile`/`--ssl-certfile` или reverse-proxy) — дольше по времени, но работает "из коробки" на любом устройстве в сети (с предупреждением о недоверенном сертификате, которое нужно один раз принять).

3. **Варьирование длины ответа** — это правка промпта, не инфраструктуры:
   - Файл: `src/agent/hermes_prompts.py` (`HERMES_SYSTEM_PROMPT`).
   - Добавить явную инструкцию: длина ответа должна соответствовать сложности вопроса — короткий/уточняющий вопрос получает короткую реплику (1 фраза), сложный/многосоставный — развёрнутый ответ. Не отвечать всегда одной "средней" длиной вне зависимости от запроса.
   - Это применимо и к текстовому чату (`demo/index.html`), и к новому `demo/call.html` — меняется один раз в промпте, работает для обоих интерфейсов.
