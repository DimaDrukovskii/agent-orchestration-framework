# Закрытый облачный стенд туристического агента

Текущий профиль: `TENANT=far_east_travel`. Таблица SQLite `market_tours` заполняется проверенными предложениями из `tenants/far_east_travel/catalog.json` при первом поиске; отдельная справка хранится в `knowledge/`. Цены сторонних организаторов и плата за вход не являются предложениями нашей компании. До загрузки собственного каталога агент не принимает бронь и оплату. Для обновления цены нужно повторно проверить страницу организатора, изменить запись и дату проверки; наличие мест отдельно не синхронизируется.

## Доступ

Для удалённого сервера требуется SSH-доступ по ключу. Владелец может зайти на сервер своим способом и добавить **публичный** ключ своего компьютера в `~/.ssh/authorized_keys`. Приватный ключ и пароль не нужно присылать в чат. Адрес сервера, пользователь и путь к ключу не сохраняются в репозитории.

Домен и HTTPS пока не настроены. Закрытый стенд запускается только на `127.0.0.1:8000` сервера; пользователь открывает его через SSH-туннель. Публиковать порт 8000 в интернет нельзя: в текущем виджете API-ключ хранится в браузере. Телефонный канал также выключен до настройки оператора, домена и вебхука.

## Предварительная проверка сервера

После появления доступа проверить ОС, память, диск, Docker и Compose. Перед запуском передать `.env` защищённым каналом, выставить права 0600, проверить `TENANT=far_east_travel`, `LLM_PROVIDER=polza`, `TTS_PROVIDER=elevenlabs`, `TELEPHONY_MODEL_PROFILE=default` и уникальный `AGENT_API_KEY`. Не выводить значения секретов в журнал.

Запуск из корня репозитория:

```bash
docker compose --env-file .env -f docker/docker-compose.yml -f docker/docker-compose.cloud.yml up -d --build app redis
docker compose --env-file .env -f docker/docker-compose.yml -f docker/docker-compose.cloud.yml ps
```

Проверка: `/health`, затем `/ready` с API-ключом. Для браузера нужен туннель `ssh -L 8000:127.0.0.1:8000 <пользователь>@<сервер>` и адрес `http://127.0.0.1:8000/demo/call.html`.

## Hermes Agent

Hermes для туризма запускается в отдельном контейнере на [официальном Docker-образе](https://hermes-agent.nousresearch.com/docs/user-guide/docker) и отдельном томе данных; существующий личный Hermes на сервере не используется. Платная подписка Nous не нужна: модель вызывается по уже имеющемуся ключу Polza. Подключение `model_profile=hermes_agent` использует OpenAI-совместимый сервер, но **не передаёт Hermes инструменты приложения**: доступ к базе подставляется в контекст, а действия менеджера и бронирования требуют отдельной интеграции. Пример MCP-конфига в `docker/hermes/appointments.yaml` относится к прежнему учебному профилю и отключён в облачном стенде. Сам Hermes API имеет доступ к инструментам внутри контейнера; его порт не публикуется наружу. До проверки функций и задержек голосовой разговор использует прямой профиль Polza.

## Перед публичным запуском

- Домен, HTTPS и защищённый вход в браузер вместо общего ключа в клиентском коде.
- Каталог собственных туров с действующими ценами, датами, местами, условиями и источником обновления.
- Интеграция с CRM/менеджером и система бронирования с подтверждением результата.
- Телефонный оператор: входящие/исходящие вызовы, вебхук, перевод и проверка реального номера.
- Метрики задержки и ошибок, оповещения, резервное копирование SQLite и тест восстановления.
- Нагрузочная проверка и проверка отказов Polza/ElevenLabs. Перезапуск контейнера помогает при сбое процесса, но не заменяет резервный маршрут при недоступности внешнего API.
