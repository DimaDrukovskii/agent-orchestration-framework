# Голосовой пайплайн: логика ElevenLabs на российских/белорусских провайдерах

ElevenLabs (`elevenlabs.io/docs/overview/intro`) не публикует архитектуру
пайплайна разговорного агента — только продукты и модели. Ниже: что у них
есть, и чем заменяем каждый блок, оставаясь в архитектуре проекта
(`src/services/tts.py` уже на этом паттерне — провайдер через env, один
интерфейс для вызывающего кода).

## Что есть у ElevenLabs (из документации)

| Блок | У ElevenLabs | Задержка |
|---|---|---|
| Realtime STT | Scribe v2 Realtime | ~150 мс |
| Realtime TTS | Eleven v4 Turbo / Flash v2.5 | 75–100 мс |
| LLM | не упоминается на странице (чёрный ящик) | — |
| Оркестрация (turn-taking, barge-in) | ElevenAgents, детали не раскрыты | — |
| Телефония | своя интеграция + сторонние SIP-шлюзы | — |

## Замена на RU/BY-провайдеров

| Блок | Кандидат | Почему | Статус в проекте |
|---|---|---|---|
| LLM | YandexGPT, Sber GigaChat, либо открытая модель (Qwen/DeepSeek) на своей инфре | Закрывает открытый вопрос локализации данных из `docs/PITCH_COMPLIANCE.md` п.1 — Claude остаётся на хакатоне, это путь в прод | не подключено, нет ключей |
| Realtime TTS | Yandex SpeechKit (`tts_provider="yandex"`) | уже есть слот в `src/services/tts.py`, только ссылка на API, токена нет | структура есть, реализации нет |
| Realtime STT | Yandex SpeechKit STT (streaming), альтернатива — Sber SaluteSpeech | обе дают потоковое распознавание на русском | не начато |
| Телефония/SIP | MTS Exolve (своя CPaaS МТС) вместо Twilio | логичнее для продукта внутри экосистемы МТС, снимает Twilio-адаптер как временное решение хакатона | не начато, Twilio остаётся адаптером хакатона (см. `docs/TRACK1_PLAN.md`) |
| Оркестрация (turn-taking, barge-in) | своя реализация поверх WebSocket | у ElevenLabs это тоже самописное — страница не даёт деталей, значит и копировать нечего, кроме идеи "потоково, не ждать полного ответа" | не начато |

## Почему не реализовано сейчас

Same паттерн, что уже принят для Yandex TTS в `src/services/tts.py`: ни одного
из токенов (YandexGPT, SpeechKit, GigaChat, MTS Exolve) в этой среде нет, и
реализация вслепую без возможности проверить — не реализация, а риск. Белорусских
провайдеров сопоставимого уровня (потоковый STT/TTS на русском) на момент
написания не нашёл — это отдельный пункт для проверки, не предположение.

## Путь к реализации (когда появятся ключи)

1. Добавить `stt_provider`/`llm_provider` в `src/config.py` — тот же паттерн,
   что `tts_provider`.
2. STT и LLM получают свой `*Service` класс (как `TTSService`), единая точка
   входа, провайдер скрыт за env-переменной.
3. Для живого звонка (не демо-чата) — WebSocket-эндпоинт вместо
   `POST /api/hermes/dialog`: STT стримит текст по мере распознавания, Hermes
   не ждёт полную фразу, TTS стримит аудио обратно по мере генерации токенов.
   Это отдельная задача, не замена текущего текстового `/api/hermes/dialog` —
   тот остаётся как есть для демо и для не-голосовых интеграций (чат-виджет,
   Telegram).
