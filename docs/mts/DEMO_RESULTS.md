# Результаты прогона демо (Трек 1)

Дата: 2026-10-09. Окружение: без реального `ANTHROPIC_API_KEY` (нет `.env` в
этой среде) — см. раздел «Что не проверено» ниже. Всё, что не требует живого
Claude API, проверено руками через `curl` и ручное открытие страниц.

## Проверено руками

| Проверка | Результат |
|---|---|
| `GET /health` | 200, `{"status":"ok",...}` |
| `GET /demo/` (чат-страница через uvicorn, тот же origin) | 200, страница отдаётся |
| `GET /demo/connect.html` | 200 |
| `GET /demo/history.html` | 200 |
| `POST /api/hermes/dialog` без `X-API-Key` | 401 |
| `POST /api/hermes/dialog` с неверным `X-API-Key` | 401, `{"error":{"code":"invalid_api_key",...}}` |
| `POST /api/hermes/dialog` с верным ключом, но фиктивным `ANTHROPIC_API_KEY` | 500 — подтверждает, что путь до Claude API дёргается, но сам Claude не отвечает без реального ключа |

**Находка, не входящая в список задач:** эндпоинт `/api/hermes/dialog` при ошибке Claude
возвращает `detail=str(e)` — технические детали ошибки Anthropic в JSON-теле
ответа (`src/api/hermes_routes.py`, `hermes_dialog`). Фронтенд (demo/index.html)
это не показывает абоненту (проверяет только статус-код), но сырой API-ответ
технический. Не исправлено — не было в списке задач, выношу отдельным пунктом.

## Что НЕ проверено (нужен реальный ANTHROPIC_API_KEY)

В этой среде нет `.env` и нет настоящего ключа Anthropic — попытка реального
диалога возвращает `authentication_error` от Claude, а не ответ агента.
Поэтому 4 сценария из `scripts/test_call.py` и таблица из 5–10 фраз ниже
**не прогнаны с живым Claude** — только задокументирован ожидаемый путь. Когда
появится `.env` с реальным ключом, прогнать:

```bash
uvicorn src.main:app --reload
python scripts/test_call.py
```

и заполнить колонку «Факт» ниже по реальному выводу.
