# Hermes Agent (ветка hermes_mts)

Отличие от базового `/api/dialog` (main): это не "запрос → один ответ от Claude",
а ReAct-агент, который сам решает, нужно ли ему свериться с данными перед ответом,
и говорит естественным языком, а не по шаблону.

## Чем отличается от main

| | main (`/api/dialog`) | hermes_mts (`/api/hermes/dialog`) |
|---|---|---|
| Логика | Один вызов Claude | Цикл: Claude может сам вызвать tool, получить результат, вызвать ещё раз |
| Данные | Нет доступа к файлам/данным | `search_knowledge_base`, `check_account_status` |
| Стиль речи | Нейтральный "оператор поддержки" | Живая речь, персонаж (Алина), без канцелярита |
| Action-логика | Отдельный вызов `determine_action` | Через tool `transfer_to_department`, который агент вызывает сам, когда решит, что нужно |
| История | Клиент передаёт `history` в каждом запросе | Сервер сам хранит по `session_id` |

## Tools агента

- **search_knowledge_base(query)** — ищет по файлам в `data/knowledge/` (тарифы, техподдержка, биллинг). Это и есть "доступ к файлам" — агент реально читает markdown и отвечает на основе него, а не придумывает цифры.
- **check_account_status(phone)** — сейчас заглушка (фиктивный баланс/тариф). Точка интеграции с реальным биллингом МТС, когда будет доступ.
- **transfer_to_department(department, reason)** — агент вызывает это сам, когда решает, что вопрос не его уровня. Реальный роутинг звонка делает сторона МТС.

## API

**POST** `/api/hermes/dialog`
```json
{
  "session_id": "call_001",
  "caller_phone": "+79991234567",
  "user_message": "у меня интернет еле работает"
}
```

Ответ:
```json
{
  "session_id": "call_001",
  "agent_response": "так, сейчас проверю... у вас роутер перезагружали в последнее время?",
  "transfer": null
}
```

История хранится на сервере по `session_id` — второй запрос с тем же `session_id` продолжит тот же разговор, `history` передавать не нужно.

**POST** `/api/hermes/dialog/stream` — то же самое, но ответ приходит потоково (для эффекта "печатает в реальном времени"). Ограничение: без tool calls в этом режиме — если по ходу диалога нужны данные, использовать обычный `/hermes/dialog`.

## Добавить новый tool

1. В `src/agent/tools.py`: добавить схему в `TOOLS_SCHEMA` + функцию-реализацию + запись в `TOOL_HANDLERS`.
2. Всё — агент сам решит, когда его вызывать, на основе `description` в схеме. Промпт менять не нужно.

## Добавить знания

Просто положить `.md` файл в `data/knowledge/`. Поиск — по ключевым словам (`search_knowledge_base`), без embeddings. Для хакатона достаточно; если нужна точность — заменить на pgvector/Supabase (уже есть в стеке).

## Что не сделано (честно)

- `check_account_status` — заглушка, не ходит в реальный биллинг
- Поиск по базе знаний — примитивный keyword match, не семантический
- `run_streaming` не поддерживает tool calls одновременно со стримом (ограничение Anthropic SDK в этой связке)
- История хранится в памяти процесса (`_sessions` dict) — упадёт сервер, пропадут сессии. Для хакатона ок, для прода — вынести в Redis
