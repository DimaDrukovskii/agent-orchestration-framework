# Когда переводить на человека

Это не инструкция по стилю речи (та — в `src/agent/hermes_prompts.py`), а
список конкретных поводов вызвать `transfer_to_department(department, reason)`.
Агент сам решает момент перевода на основе этого списка, а не каждый раз
додумывает заново.

## Прямая просьба абонента

Абонент явно просит человека/менеджера ("соедините с человеком", "позовите
менеджера", "мне нужен специалист") — переводить сразу, без попытки решить
самому. Отдел: `[менеджер]`. Reason: "абонент явно попросил человека".

## Вопрос за пределами того, что знает агент

Вопрос не покрыт `services_and_pricing.md` / `support_faq.md`, и
`search_knowledge_base` не нашёл релевантного файла — не придумывать ответ.
Отдел: `[уточнить по теме — продажи/техподдержка/биллинг]`. Reason: "нет
данных по вопросу в базе знаний".

## Нерешённая проблема после двух попыток

См. `support_faq.md` — если шаги не помогли, не повторять то же самое
третий раз. Отдел: `[техподдержка]`. Reason: "стандартные шаги не помогли".

## Вопрос про деньги, который требует проверки по счёту

Если `check_account_status` вернул что-то, что агент не может объяснить
сам (несовпадение, спорная сумма) — не спорить с абонентом и не угадывать.
Отдел: `[биллинг]`. Reason: "расхождение по счёту, нужна проверка".

## Явная агрессия/эскалация тона

Абонент выражает серьёзное недовольство, грозит жалобой/расторжением — не
продолжать стандартный сценарий. Отдел: `[менеджер]`. Reason: "высокий
риск недовольства клиента".

## Отделы — список для этого бизнеса

Заменить на реальные отделы конкретного бизнеса (сейчас плейсхолдер,
совпадает с `enum` в `TOOLS_SCHEMA` в `src/agent/tools.py` — если меняешь
список здесь, поменяй и там, иначе agent будет вызывать значение, которого
схема не разрешает):

- `[менеджер]`
- `[техподдержка]`
- `[биллинг]`
- `[продажи]`
